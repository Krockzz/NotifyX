# NotifyX Frontend — Project Instructions

## Project overview

NotifyX is a developer-focused Notification-as-a-Service (NaaS) platform. It allows users to create applications, configure supported notification channels, manage API keys and templates, send notifications, and monitor delivery status.

The backend already exists as a separate part of the project. The frontend must integrate with the real backend when API integration begins.

## Technology requirements

- React Router v7 in Framework Mode.
- JavaScript, not TypeScript.
- Follow the conventions of the existing generated project.
- Inspect the existing dependencies before installing new ones.
- Use reusable React components and clear separation of concerns.
- Use a consistent styling system across all pages.

## Design direction

- Professional, modern SaaS product.
- Developer-first visual identity.
- Light landing page with restrained indigo and purple accents.
- Generous spacing, clear typography, subtle borders, and polished interactions.
- Responsive layouts for desktop, tablet, and mobile.
- Accessible navigation, buttons, forms, and color contrast.
- Avoid excessive gradients, unnecessary animations, and generic template-like sections.

## Development rules

- Inspect existing files before making changes.
- Do not recreate or replace the project from scratch.
- Do not modify backend files when working on frontend-only tasks.
- Do not add dependencies without a clear reason.
- Keep components maintainable and avoid unnecessary duplication.
- Do not invent backend endpoints or claim unsupported features work.
- Do not present fabricated statistics, testimonials, or customer counts as real.
- Never expose API secrets, private keys, or credentials in browser-side code.
- Run relevant build, lint, or other available checks after changes.
- Summarize changed files and any remaining issues after each task.

## Current milestone

Build the public NotifyX landing page only.

Do not implement authentication, the authenticated dashboard, or backend integration in this milestone. First inspect the existing project and propose an implementation plan before editing files.
